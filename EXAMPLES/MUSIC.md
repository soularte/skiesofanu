# Музыка по книгам

Музыкальные карточки заполняются в Markdown, как карточки книг. Менять TypeScript или страницу `music.astro` не нужно.

## Добавление песни

1. Положите аудиофайл в `public/audio/`, например `public/audio/new-song.mp3`.
2. Откройте файл нужной книги в `src/content/music/`. Для новой книги создайте там файл по образцу ниже.
3. Добавьте песню в `tracks`. Поля `title`, `credit`, `src`, `lyrics` отвечают за название, подпись, аудио и текст. Текст необязателен: без него ссылка «Текст песни» не показывается.

```yaml
---
# Идентификатор книги — имя её файла в src/content/books/ без .md.
book: aviatory
# Порядок книг в музыкальном меню. Меньшее число — раньше.
order: 1
# Необязательный светлый фоновый узор.
pattern: /images/music/aviatory-pattern.webp
# true скрывает всю музыкальную подборку со страницы.
draft: false
tracks:
  - title: "Название песни"
    credit: "На стихи Имя Фамилия | Исполняет Имя Фамилия"
    src: "/audio/new-song.mp3"
    lyrics: |-
      Первая строка
      Вторая строка

      Следующая строфа
  - title: "Ещё одна песня"
    credit: "На стихи Имя Фамилия | Бортжурнал. Suno"
    src: "/audio/another-song.mp3"
---
```

В файле сохраняйте разделители `---` в начале и конце настроек. Каждая песня начинается с `- title:`. Используйте пробелы для отступов, а строки текста под `lyrics: |-` сдвигайте на шесть пробелов. Пустые строки разделяют строфы. Порядок песен в файле — порядок карточек на странице.

## Связь с книгами

Создавайте один музыкальный Markdown-файл на книгу. Название и изображение книги берутся из её существующей карточки. Меню на странице «Музыка» заполняется автоматически: в него попадают только книги с хотя бы одной настоящей песней и `draft: false`.

Переход из книги на музыку по-прежнему задаётся в оформлении книги, в `extraLinks`:

```yaml
extraLinks:
  - label: "Музыка по книге"
    url: "/music/#aviatory"
```

Замените `aviatory` на идентификатор нужной книги. Шаблон страницы книги менять не требуется.

## Демонстрационные карточки

Для примерки оформления можно добавить трек без записи:

```yaml
  - title: "Условное название"
    credit: "Инструментальная тема · демотрек"
    demo: true
```

У демотрека нет плеера. Книга только с демотреками не попадает в музыкальное меню. Когда запись готова, уберите `demo: true` и добавьте `src`.

При сборке проверяются обязательные поля, ссылка на существующую книгу, формат пути и наличие аудиофайлов и узоров. Повторная подборка для той же книги или одинаковые ссылки на треки останавливают сборку с понятной ошибкой. Сборка выполняется командой `npm run build`.

Поле `pattern` задаёт фоновый узор подборки. Файл WebP или SVG помещается в `public/images/music/`; поле можно убрать для подборки без узора. На десктопе декоративное пространство под треками равно высоте одной закрытой карточки; на мобильных оставлено 32 px.

Размер узора задаётся полем `patternSize: 960` (ширина в пикселях). По умолчанию — 480. Чем больше число, тем крупнее рисунок.

Для цельной иллюстрации без повторения добавьте `patternRepeat: no-repeat`: фон заполнит ширину плашки; на узком экране края будут обрезаны с сохранением масштаба. По умолчанию узор повторяется.

## Данные для поиска и публикации

Песни получают постоянные ссылки автоматически из имени аудиофайла, например `/music/#aviatory-sestra-i-brat`. Старайтесь не переименовывать уже опубликованные аудиофайлы: от этого зависят ссылки и сохранённая позиция прослушивания.

Для разметки поисковиков можно дополнительно заполнить поля трека:

```yaml
    lyricist: Екатерина Комарова
    performer: Диана Терентьева
    duration: PT3M44S
```

Это отдельные необязательные поля: `lyricist` — автор стихов, `performer` — известный исполнитель, `duration` — длительность аудио (3 минуты 44 секунды в этом примере). Указывайте только достоверные сведения. Видимая подпись по-прежнему полностью задаётся в `credit`. Не нужно указывать исполнителя, если он неизвестен.

Страница автоматически добавляет разметку подборок, песен и аудиофайлов. Все названия, подписи и тексты присутствуют в HTML до выполнения JavaScript. Сборка проверяет существование аудиофайлов и фоновых рисунков.

SEO-описание страницы хранится в `src/data/seo.json`, подпись изображения для соцсетей — в `src/data/social.json`. Для обновления только музыкальной карточки соцсетей: `npm run social:generate -- --route=/music/`.

Проверки мобильного поведения и шаги после публикации: [MUSIC-RELEASE.md](MUSIC-RELEASE.md).
